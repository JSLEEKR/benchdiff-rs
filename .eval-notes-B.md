## Eval-A's 5 observations — outcomes

1. **`cohens_d` / `rel_change` → JSON `null`** — **VERIFIED as real bug, FIXED (MEDIUM)**.
   Reproduced: baseline `[0,0,0]` vs current `[1,1,1]` → `"cohens_d": null, "rel_change": null`. Strictly-typed consumers crash.
   Fix: introduced `compare::INF_SENTINEL = 1e300`. `compute_row` saturates `rel_change` and `cohens_d` to `±INF_SENTINEL` whenever the underlying math would produce `Inf`. JSON now stays strictly numeric. Human-facing formatters (`fmt_ns`, `fmt_pct`, new `fmt_d`) collapse values `>= 1e100` back to `∞` / `±∞` so terminal and markdown output stay readable. Regression tests added: `json_output_has_no_null_numerics_when_infinite`, `zero_baseline_mean_saturates_to_sentinel`, plus `fmt_pct_saturation_sentinel`, `fmt_ns_saturation_sentinel`, `fmt_d_basic_and_infinite`.

2. **`main.rs` exit code by substring match** — **VERIFIED fragile, FIXED (MEDIUM)**.
   On Windows the `"no such file"` substring never matches — the "I/O" substring accidentally saved us. Rewrote `main.rs::classify_exit_code` to downcast `anyhow::Error` → `benchdiff::Error` and switch on the variant. Documented exit codes (0/1/2/3/4/5) preserved. Manually verified: missing file still exits 4; regressions still exit 1; config errors exit 2.

3. **Criterion `parse_dir` depth / symlink cycle** — **VERIFIED, FIXED (MEDIUM)**.
   Original `walk` was unbounded recursion with no symlink detection. Added `MAX_WALK_DEPTH = 32` (Criterion trees are 3–4 deep in practice), explicit rejection of symlink entries via `symlink_metadata()`, and a regression test `deeply_nested_directory_is_rejected` that constructs a 37-level nested path and confirms the walker errors instead of stack-overflowing.

4. **`DiffRow.baseline_mean_ns` field name wrong for Ops/Bytes** — **VERIFIED, LEFT AS LOW**.
   Renaming `baseline_mean_ns`/`current_mean_ns` is a breaking JSON-schema change and the bug is purely cosmetic: the value is correct, only the suffix is misleading for non-time units. Documented in comment inside `compute_row`; not changing the public schema in a patch-level audit.

5. **`Config.tolerance` bypasses `deny_unknown_fields`** — **VERIFIED, FIXED (LOW-MEDIUM)**.
   `tolerance` is a `toml::value::Table` so serde's `deny_unknown_fields` only guards the outer level. `tolerance_for` silently called `.as_float()` → `None` for anything that wasn't a float (e.g. `"foo" = "0.2"` → ignored, not an error). Added per-entry validation in `Config::validate()` that rejects non-numeric or negative entries and also accepts TOML integers as a friendly extension. Regression tests: `validate_rejects_non_float_tolerance`, `validate_rejects_negative_tolerance`, `validate_accepts_integer_tolerance`.

### B5 — `glob_match` does not handle middle wildcards (MEDIUM)
**NEW in eval B.** The README promises "glob-lite patterns" and eval B's prompt explicitly probes `ignore = ["Bench*Skip"]`. The original matcher only handled `*` at prefix, suffix, or both ends. A pattern like `Bench*Skip` would be treated as an exact literal and never match `BenchFooSkip`, silently producing a regression verdict instead of an ignore. Users would think they'd disabled a flaky bench and get CI failures anyway.
Fix: rewrote `glob_match` to split on every `*` and walk middle chunks in order. Supports `Bench*Skip`, `Bench*Foo*Bar`, and still handles the old prefix/suffix/contains cases. Existing tests all pass. New tests: `ignore_glob_middle_wildcard`, `ignore_glob_multiple_wildcards`. README config example updated.
