## Bugs found

### Bug 1 — Ops unit verdict direction inverted (HIGH severity) — `src/compare.rs`

`compute_row` treated `mean_b > mean_a` as a regression unconditionally, ignoring
`Unit::is_time()`. For `Unit::Ops` (throughput, higher = better) this meant a
benchmark that doubled its ops/sec was flagged as a **Regression** and CI would
fail with exit 1.

Reproduction (pre-fix):

```
baseline: throughput = 100 ops  (6 samples)
current:  throughput = 200 ops  (6 samples)
$ benchdiff compare ... --output json
"rel_change": 1.0,
"verdict": "Regression"    ← wrong; should be Improvement
exit=1                     ← would break CI for anyone using `ops` unit
```

Fix: thread `Unit` into `compute_row` and invert the direction for `Unit::Ops`.
`Unit::Bytes` keeps the default direction (higher memory/allocation = worse),
matching the unit's documented semantic in `sample.rs`. `is_time()` already
existed on the enum but had zero call sites — dead API that the audit
surfaced.

New tests (`src/compare.rs`):
- `ops_increase_is_improvement_not_regression`
- `ops_decrease_is_regression`
- `bytes_increase_is_regression`

### Bug 2 — Gobench NaN/inf error reports wrong field (MEDIUM severity) — `src/parsers/gobench.rs:52-54`

```rust
if !value.is_finite() {
    return Err(Error::NonFinite {
        name: entry.0.iter().len().to_string(),   // !!
    });
}
```

The `Error::NonFinite { name }` field is the benchmark name. The code was
passing the string representation of the aggregated samples vec length,
producing error messages like `NaN or infinity in benchmark value ("0")`
which is actively misleading when diagnosing real CI failures.

Additionally the error branch was placed *after* `agg.entry(name).or_insert_with(...)`,
which means a poisoned benchmark got registered in the aggregation map even
though we abort. Minor but wasteful.

Fix: move the finite check before the entry insertion, and set
`name: name` from the parsed line. Also improved the "unit changed mid-run"
error to include the benchmark name (and eliminated a `format!` string literal
with no interpolation — clippy pedantic would flag `useless_format`).

New tests:
- `nonfinite_error_reports_real_name`
- `nonfinite_inf_reports_real_name`

## Observations (non-blocking)

1. **`cohens_d` serializes as JSON `null`** when the pooled variance is zero
   and the means differ (`f64::INFINITY`). `serde_json` writes non-finite
   floats as `null`. Not strictly a bug — the Welch result already carries
   the correct verdict — but downstream consumers iterating rows as strictly
   typed `f64` will get a deserialize error. Worth documenting; not fixed in
   this cycle.

2. **Exit-code detection in `main.rs`** uses substring matching on the Debug
   representation of the error chain (`chain.contains("parse")`, `"I/O"`, etc).
   Fragile — if an error message happens to contain those substrings for
   unrelated reasons, the exit code is wrong. Worth refactoring to
   `matches!(err.downcast_ref::<Error>(), ...)` in a future cycle.

3. **`Config.tolerance` is `toml::value::Table`** so `deny_unknown_fields` does
   not apply to it. That's intentional (tolerance names are benchmark-defined)
   but worth noting — non-float values silently fall through `as_float()` and
   behave as "no override".

4. **`EstimatePoint::value` fallback chain** `estimate.or(lower_bound).or(upper_bound)`
   will use `upper_bound` as the synthesized mean if the estimates file is
   corrupted in an unusual way. Minor.

5. **Criterion `parse_dir` recursion has no depth cap or symlink cycle
   detection.** On real criterion output this is fine. A malicious input tree
   could cause stack exhaustion via symlink loops. Out of scope for a
   dev-facing CLI on trusted local files — noting for completeness.

6. **`baseline_mean_ns` field name in `DiffRow`** is literally "ns" but holds
   the normalized sample value for non-time units too (ops count, byte count).
   Cosmetic — rename or add a `unit` field in a future cycle.
